# Simulant（仿生石）相容適配

DACT 0.4.3.0 只提供使用者自行匯入的 Simulant 的執行時適配。未安裝時不顯示入口、推薦或專屬許可權項；產品不下載、不捆綁 Simulant。

## 使用者手動匯入

1. 使用者自行取得原版 `Simulant.dll`，透過 DACT 現有「安裝 DLL / ZIP」匯入。
2. 手動匯入後彈出授權提示，確認前保持禁用；確認後才進入對應 Host。擴充套件頁提供啟停、開啟原版配置及垃圾桶圖示刪除按鈕。刪除前正常停止對應 Host，原檔案移入備份目錄。Simulant 在共享 Host 中排在 PostNamazu、MnFeN Triggernometry 兩項依賴之後載入。
3. 在同頁許可權區啟用 Simulant 的「原生遊戲記憶體」，以及 PostNamazu 的「遊戲命令」「原生遊戲記憶體」。原有完整許可權決定不會自動為 Simulant 授權。
4. 開啟原版配置，CSV 載入完成後由使用者手動初始化。安裝、啟用、開啟配置均不會自動初始化或開啟防火牆。
5. 簽名掃描出現失敗或空結果時，初始化保持失敗，原版介面顯示具體地址錯誤。
6. 退出遊戲前先停止模擬，再取消“啟用防火牆”，確認收發包恢復後退出遊戲。“退出模擬”僅返回真實區域，不會關閉防火牆。

## 已驗證版本與實現

離線驗證使用上游 v0.0.4.2，DLL 大小 28,793,856 位元組，SHA-256：
`12F31A446D6F137A7D0B39939F9E0361240D9209AC3677624FF95431C2578467`。
安裝器保留使用者原始 DLL，Host 在載入時轉換舊版 WinForms NRBF 資源，繼續禁用 BinaryFormatter；內嵌 CSV 與原版模擬邏輯保留。

FFXIV facade 同步繫結，替換 ACT 狀態標籤無限輪詢及對應的無效退訂。解除安裝仍執行原版防火牆恢復，最多等待 5 秒，再解除安裝 PostNamazu。
原生初始化和防火牆啟用同時要求 Simulant 自身原生記憶體許可權與 PostNamazu 的兩項原生執行許可權。

函式入口被已有 Hook 改寫時，原版基於實時記憶體的掃描可能找不到 OnSendPacketFuncPtr / ActionManager.UpdateFuncPtr。僅對這兩項失敗增加原始遊戲映像回查：PE 頭和映像大小必須一致（ImageBase 只允許原值或實際 ASLR 基址），簽名必須唯一，執行時函式體必須保持一致，入口只接受已知 E9 / FF25 / FF2425 跳轉。其他不匹配仍中止初始化。
發包防火牆把已有跳轉轉換為指向原目標的絕對跳轉後放入程式碼洞，保留 Hook 鏈；用於恢復入口的原始備份不變。程式碼洞分配在入口附近，入口只寫入 5 位元組 E9，避免原版 15 位元組覆蓋破壞已有 Hook 返回到 +7 / +10 的位置。開啟前檢查入口，先安裝發包 Hook；後續失敗時恢復已修改的收發包入口。
2026-09-14 實機確認修復後的地址掃描為 64/64，初始化成功。首次防火牆測試暴露了 15 位元組覆蓋與已有回跳位置衝突導致的崩潰；短入口修訂透過測試程序內真實執行的心跳放行、普通包攔截和恢復迴歸。使用者已確認修訂版初始化和防火牆開啟成功；只讀檢查確認 5 位元組發包入口及收包攔截補丁生效。02:59:02.8 使用者日誌顯示收發包 Hook 和防火牆均關閉，隨後只讀快照確認原有發包 Hook 和收包入口指令恢復，遊戲程序仍在執行。

地圖列表開頭是上游預留的空名稱記錄。勾選“僅顯示含預設區域”可顯示 755、1122、1238、1363 四個區域；已驗證 1122 的兩個模擬預設可選擇。按使用者要求保留原版預設篩選行為。
使用者另反饋實機勾選篩選時視窗短暫無響應，隨後明確確認已自行恢復正常；暫未確定卡頓原因，未據此修改篩選邏輯。

開始按鈕現在要求初始化、防火牆和模擬區域均就緒，階段切換已結束，且遊戲當前地圖與預設一致。原版只憑已選預設即可啟動，曾在進入副本前或返回旅店後仍顯示“模擬已開始”。不滿足條件時保留當前會話並提示原因，不自動切換地圖；載入區域時新增請求日誌。修訂版實機於 03:13:04 收到載入 1122 請求，隨後只讀檢查確認遊戲地圖由 177 變為 1122；使用者明確說明此前是操作問題。使用者隨後確認歐米茄絕境 P6 宇宙天箭正常，日誌包含先內側和先外側多次啟動、停止。

原版 v0.0.4.2 的 P3 螢幕探測描述為“佔位符”，`U6b3_屏幕探测Logic.OnStart()` 和 `OnStop()` 均直接丟擲 `NotImplementedException`；已核對原版 DLL 的 IL 與原始碼，和實機錯誤一致。這是上游尚未實現的預設，DACT 相容適配不包含補寫其機制；P3 地圖/階段載入與 P3 機制可用性應分別判斷。

絕伊甸 P5 地火曾在生成 EObj 後立即查詢實體時報找不到物件，導致整條時間軸中斷；只讀檢查確認遊戲中已有 BaseId 2014199 的場景物件。Host 實體增量約每 30 毫秒同步，無法滿足原版生成後立刻回查的要求。原生掃描完成後，Simulant 的實體列舉改用原版 GameObjectManager / GameObjectPtrs 直接讀取即時列表，保留自身及 PostNamazu 的許可權檢查；掃描前仍使用 Triggernometry 原有列表。迴歸透過原版 DLL 和託管記憶體夾具驗證無 IPC 更新時新 EObj 可立即查詢、撤銷許可權後不讀取。53f5306 修訂已覆蓋本機，重啟後確認實際 Host 為該修訂並進入區域 1238；使用者隨後明確反饋“沒問題了”，絕伊甸 P5 地火本輪實測透過。

上游釋出說明標註 7.55。本機國服 `2026.09.01.0000.0000`（7.56）的磁碟 `.text` 節中，原版 DLL 的 64 組簽名全部存在唯一匹配；這是靜態檢查，不驗證執行時記憶體佈局、地圖切換、實體生成或防火牆恢復。
上游目前沒有宣告許可證，未確認作者對適配的授權；DACT 僅提供相容程式碼，不重新分發其原始碼或 DLL。

## 維護者驗證

常規 Package / Host smoke 覆蓋手動匯入前無安裝記錄、專用分類、預設許可權、全部 8 種許可權組合與簽名檢查。
使用維護者自行提供的固定原版 DLL 執行整合測試：

```powershell
$env:ACTCOMPAT_SIMULANT_DLL = '绝对路径\Simulant.dll'
& 'tests/DalamudActCompat.PackageSmokeTests/bin/Release/net10.0-windows10.0.17763.0/DalamudActCompat.PackageSmokeTests.exe'
& 'tests/DalamudActCompat.HostSmokeTests/bin/Release/net10.0-windows10.0.17763.0/DalamudActCompat.HostSmokeTests.exe' `
  --simulant $env:ACTCOMPAT_SIMULANT_DLL 'vendor/BundledActPlugins'
```

測試載入真實 PostNamazu、Triggernometry 和 Simulant，驗證原版介面、CSV、依賴順序、缺失授權/遊戲程序時的錯誤、Triggernometry 回撥、ACT 日誌、實體地址與正常解除安裝。CI 中下載的固定 DLL 僅作為臨時測試輸入，不進入產品包。
啟動條件迴歸覆蓋正確區域、未載入、載入中、地圖不匹配和防火牆關閉；原版點選處理函式在未初始化時不會建立會話。原生迴歸僅在測試程序內分配合成函式，復現 FF2425 Hook 返回到入口 +10 的情況，不修改遊戲程序。遊戲內初始化、防火牆開啟/關閉恢復、地圖切換及 P6 宇宙天箭已驗證；不據此宣稱所有區域和預設均已驗收。
