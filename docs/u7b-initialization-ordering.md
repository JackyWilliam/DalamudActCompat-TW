# 絕妖星 P1 初始化順序補償

當地圖 1363 的場景物件尚未同步到 Host 時，Triggernometry 2.2 的 `111/019D`
轉換會生成 BaseId 為 0 的 `1019D`。U7b v1.0.5 的原始初始化條件要求
BaseId 2015156，因此這一事件無法進入 P11a；後續冰火與散攤事件也無法生成繪圖。
獨立 Host 中，物件延後 50 ms 的輸入可復現此問題。50 ms 是測試安排，不是閾值；
尚未取得此前實際失敗場次的完整日誌，不能斷言所有缺圈都由此造成。

Host 僅在上述地圖遇到物件缺失或 BNpcID 尚未就緒的 `111/019D` 時，暫存
Triggernometry 的原始日誌及其後續事件。全量快照或有效實體增量到達後，按順序交給
原版轉換器。其他 ACT 擴充套件繼續正常接收日誌，原 XML、條件、動作和繪圖引數均保留。

TN 的事件執行緒和動作執行緒是兩個佇列。集中釋放積壓日誌會讓冰火條件早於初始化動作
執行。因此，恢復的 P1 初始化還需等待原動作 `UnsetRegexUniversal ^U7b11a`
完成；以外掛例項、原事件時間及物件 ID 匹配完成訊號，再釋放後續日誌。
觀察器異常不向上游動作執行緒傳播。未命中初始化條件或使用者禁用該條目時也不會無限等待。

等待總上限為 500 ms，佇列最多 1024 條 / 1048576 個字元。到期或超限時，一次性
按原順序放行，不補發、不去重；這是回退到原行為，不能修復永久缺失的物件。
切地圖、撤銷日誌許可權或解除安裝外掛會清理待處理內容。物件已經就緒、匯入日誌、
其他地圖及舊版轉換 ABI 保持原路徑。
